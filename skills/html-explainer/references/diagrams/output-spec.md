# 図の大きさ・文字サイズ・文書への組み込み

`index.md` から参照されます。図の `viewBox`、文字サイズの階層、文書への組み込み方、図を減らす順序を定めます。

## 1. 大きさ

図は文書の本文幅(`.mb-figure-frame` の内側幅 約909px)に収めます。

| 項目 | 値 |
|---|---|
| `viewBox` の幅 | `908`(4の倍数で、本文幅いっぱいに収まる最大値) |
| `viewBox` の高さ | 内容に合わせた4の倍数。標準は `600`、目安は `300`〜`680` |
| 外側の余白 | 4辺とも 40px(密な図は 24px まで詰めてよい)。枠の padding 24px と合わせて、内容と枠の罫線の間は 64px(詰めた場合は 48px)になる。内容を `viewBox` の端に触れさせない |
| 凡例の帯 | 内容の下に 60px(その下に外側余白 40px)。凡例のキーと、同じ行の右寄せの出典・注記の行だけを置く |

`type-*.md` の例が `960` 幅で書かれていても、`908` 幅で座標を計算し直します。型の式は幅をパラメータとして持つものが大半です。

内容の外接矩形から決める場合は、外接矩形を4の倍数に切り上げ、固定の余白(外側 40px、下に凡例 60px)を足します。

## 2. 文書への組み込み

図は `.mb-figure` と `.mb-figure-frame` に入れます。`.mb-figure-frame` は白地・黒の罫線・角丸の表示面です。

```html
<figure class="mb-figure">
  <div class="mb-figure-frame diagram-scroll" tabindex="0" role="region" aria-label="図1 注文が確定するまでの流れ(横にスクロールできます)">
    <svg viewBox="0 0 908 600" role="img" aria-labelledby="flow-title flow-desc"> … </svg>
  </div>
  <figcaption>図1　注文が確定するまでの流れ</figcaption>
</figure>
```

`tabindex="0"`・`role="region"`・`aria-label` は、横スクロールの枠をキーボードで操作でき、読み上げで図の名前が分かるようにするためです。`aria-label` の末尾に「横にスクロールできます」と書いて、スクロールできることを知らせます。図番号は「図1」と書きます。

### 狭い画面で読める大きさを保つ

SVG が画面幅へ縮むと、文字も一緒に縮みます。スマートフォンでは 12px の名前が数pxになり、読めません。図の幅を `viewBox` の幅に固定し、枠の中で横にスクロールさせます。`document.css` の `figure.mb-figure svg { max-width: 100%; }` を図に限って打ち消すため、文書の `<style>` に次の4規則を1度だけ書きます。`min-width` は、使う `viewBox` の幅と必ず同じ値にします。

```css
.diagram-scroll { overflow-x: auto; }
figure.mb-figure .diagram-scroll svg { display: block; width: 100%; min-width: 908px; max-width: none; height: auto; }
@media print {
  .diagram-scroll { overflow-x: visible; }
  figure.mb-figure .diagram-scroll svg { min-width: 0; max-width: 100%; }
}
```

印刷には横スクロールがありません。印刷では `min-width` と `overflow-x` を解除し、図を紙に収めます。この規則は、通常の規則より**後**に書きます。メディアクエリは詳細度を上げないためです。祖先に `overflow: hidden` があると、SVG はスクロールせず切り取られます。`.diagram-scroll` は、その祖先の**内側**に置きます。

## 3. 文字サイズの階層

役割ごとの値です。名前の書体は sans、技術的な値は mono です(`style-guide.md`)。

| 役割 | サイズ |
|---|---|
| ノードの名前(sans 600) | 12 |
| 副ラベル(mono) | 9 |
| 矢印ラベル(mono) | 8 |
| eyebrow・タグ(mono) | 8 |
| ノードの箱の最小の高さ | 48 |
| ノード間の最小の間隔 | 24 |

すべての `font-size` は、上の値か、次の例外のどれかにします。

| 例外 | 書体 | サイズ |
|---|---|---|
| 密な注記: 凡例のキー、軸の目盛り、データラベル、出典の行、箱内のタグ | mono または sans regular | 7〜11(半端な 0.5 刻みも可) |
| チャートの系列名・行名: 棒のカテゴリ、折れ線・バンプの系列、ガントの行、行列の見出し | sans 600 | 10〜11 |
| グループ・エンティティの見出し | sans 600 | 14 |
| 不透明度 0.08 以下の装飾的な透かし数字 | 任意 | 任意 |

例外は隣の書体に結び付いています。sans 600 以上はノード名の声で、細い sans は注記です。ノード名が注記の範囲(7まで)へ下りることも、mono の目盛りが見出し用の14を借りることもできません。これ以外のサイズは図の欠陥です。新しいサイズとして扱いません。日本語のラベルは 12px を下限にします(`style-guide.md` の「日本語ラベル」)。例外の 7〜11 と 10〜11 は、ラテン文字と数字だけの目盛り・データラベル・出典・系列名に使います。日本語を含む文字は、例外の表より日本語の下限(12px)が先に効きます。ラテンの識別子を矢印ラベルにするときは、mono 9〜10px まで上げてかまいません。

## 4. 図を減らす順序

内容が上限(`index.md` §5、`layout-budget.md`)を超えるときは、次の順で削り、上限に収まった時点で止めます。場当たりに削りません。

1. **完全な重複:** 同じ形のN個のワーカー・レプリカ・シャードを、`Worker ×N` の1ノードにする
2. **葉だけの集まり:** 子がすべて葉のコンテナは、コンテナ1つにまとめる(3つの箱を `コアサービス` 1つにする)
3. **話を変えない次数1の末端:** 監視のフック、ログの置き場、アーカイブ層
4. **横断的な基盤:** ログ、メトリクス、シークレット、CI。図の主題でなければ最大1つまで
5. **それでも超える:** 概要と詳細に分ける。縮めずに分ける

2〜5で削ったものは、本文で一言触れるか、図の説明に書きます。読み手は図に無いものを見られません。

固有名詞は原典の語彙を保ちます。`Kafka` を `メッセージバス` と呼ぶのは構いませんが、`Event Grid`(別の製品)と呼ぶのは事実の誤りです。入力に `svc-04` とだけあって説明がない場合は、業務名を推測せず識別子のまま使い、利用者に確認します。

## 5. 点検項目

`index.md` §6 の点検と合わせて確認します。

- [ ] `viewBox` の幅が `908`、高さが4の倍数か
- [ ] `.diagram-scroll` の `min-width` が `viewBox` の幅と等しいか
- [ ] `@media print` の規則が、通常の規則より後ろにあるか
- [ ] 外側の余白 40px、凡例の帯 60px を守っているか
- [ ] 文字サイズが役割の値か例外の範囲か。日本語のラベルが 12px 以上か
- [ ] ノード数が上限(9。`layout-budget.md` の型ごとの値)以内か
- [ ] `<svg>` に `role="img"`、解決する `aria-labelledby`、最初の子の空でない `<title>`、空でない `<desc>`、図ごとに一意の ID があるか
