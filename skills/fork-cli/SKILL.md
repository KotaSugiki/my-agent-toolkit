今のセッションをメインセッションとして残し、実装または文書作成の1件を、利用者が選んだ CLI で実行してください。メインセッション自身はその実装も文書作成も行いません。

1件は、この呼び出しで指定された、実装または文書作成のどちらか一方の依頼です。区切りはファイル数、関数、コミットではありません。範囲は、フォークに書く目標、対象外、関連パスです。関連パスは複数のファイルになってよいです。実装と文書作成の両方が必要なら、呼び出しを分け、フォークを2件作ってください。

フォークは、その1件に必要な決定と範囲を作業ディレクトリへ書いた記録です。会話全体は写しません。

## 1. 依頼を確定する

種類（実装または文書作成）、引き継ぎ先の CLI 名、作業ディレクトリがそろうまで、ファイルの作成と起動に進まないでください。種類か CLI 名が欠けていれば、フォークを書く前に利用者へ尋ねてください。作業ディレクトリの指定がなければ、カレントディレクトリを使ってください。

完了は、この3つが明示されていることです。

## 2. フォークを書く

[記録項目](references/fork.md)の共通の節と、選んだ種類の節を読んでください。ほかの種類の節は読みません。

`.fork-cli/<実行ID>/fork.md` を書いてください。実行IDは日時と、依頼を表す短い識別子です。書く内容は、目標、既に決まっていること、対象外、関連パス、その種類の追加項目、メインセッションへ戻してほしい結果です。

決まっていることが既存の文書、計画、Issue、差分にある場合は、本文を繰り返さずパスまたは URL を書いてください。API キー、パスワード、個人を特定できる情報は書かないでください。

同じ実行IDの `fork.md` を、引き継ぎ先と同時に更新しないでください。このファイルを書き終えてから起動します。

完了は、選んだ種類に必要な項目が `fork.md` にあり、会話全体の写しではないことです。

## 3. 引き継ぎ先を起動する

[起動形](references/clis.md)では、選んだ CLI の節だけを読んでください。一覧にない CLI は、未登録の節を読んでください。

起動前に、その CLI の `--help` で、非対話のプロンプト指定と、対話の承認待ちを出さない権限モードがあることを確認してください。ヘルプと `references/clis.md` が違えば、ヘルプを優先してください。必要なフラグが確認できない場合は、起動せずに不足を伝えてください。

ファイルの変更と、フォークに書かれた確認コマンドだけを自動承認してください。全権限の迂回は、利用者がその実行で指定したときだけ使ってください。`references/clis.md` に書かれた迂回用のフラグを、指定がない実行の既定にしないでください。

[記録項目](references/fork.md)のプロンプトの節に従い、`.fork-cli/<実行ID>/prompt.md` を書いてください。このプロンプトを、ヘルプが標準入力を読むと示している CLI では標準入力で渡してください。長いプロンプトをコマンドライン引数へ埋め込まないでください。作業ディレクトリは、手順1で決めたディレクトリにしてください。

プロセスは、メインセッションの次の入力を待たずに進むように開始してください。起動した命令は、秘密情報を除いて `.fork-cli/<実行ID>/launch.md` に残してください。残す項目は、実行ファイル、引数、作業ディレクトリ、プロンプトの渡し方、取得できたプロセスIDです。

完了は、プロセスを開始したこと、または開始せずに不足を伝えたことです。

## 4. 完了を確認する

完了の合図は、`result.md` の末尾にある `状態: 完了` です。プロセスの終了だけでは完了にしないでください。`result.md` を書くのは引き継ぎ先だけです。

メインセッションの CLI が提供するサブエージェント機能で、完了確認だけのサブエージェントを1つ起動してください。特定製品のサブエージェント用コマンドは、このスキルに固定しません。このサブエージェントは実装も文書作成も行わず、`result.md` とプロセスの終了だけを見てください。`状態: 完了` があるまで待ち、見つかったらその絶対パスをメインセッションへ返してください。プロセスが終了し、印が無い場合は、待たずに失敗として返してください。

印が見つかったら、メインセッションは `result.md` を読み、結果と残件を短く述べてください。引き継ぎ先の作業はやり直さないでください。

プロセスが終了し、印が無い場合は、失敗として終了コードと `launch.md` のパスを伝えてください。終了コードが取れたら `launch.md` に追記してください。

その CLI がサブエージェントの終了まで親の会話を止める場合は、メインセッションもその間止まります。利用者は、待ちをやめるよう伝えられます。固定の待ち時間は置かないでください。

サブエージェントを起動できないとき、または起動に失敗したときは、次の節へ進んでください。別の製品のサブエージェントコマンドへ切り替えないでください。

完了は、印を読んで結果を述べたこと、失敗を伝えたこと、または次の節へ移ったことです。

## 5. サブエージェントを使えないとき

利用者に、監視できないこと、完成後の `result.md` の絶対パス、戻るときに貼る文面を伝えてください。文面は [記録項目](references/fork.md)の戻り文面です。

利用者が戻ったとき、ファイルが無い、または `状態: 完了` が無い場合は未完了と伝え、結果の要約を始めないでください。印がある場合は、手順4と同じ読み方をしてください。プロセスが終了しているのに印が無い場合も、手順4の失敗の伝え方にしてください。

完了は、未完了と伝えたこと、または印を読んで結果を述べたことです。

## 応答で伝えること

`.fork-cli/` は、利用者がコミットを頼んだとき以外、コミット対象に含めないでください。応答でそのことを伝えてください。このディレクトリを `.gitignore` へ自動では追加しないでください。
