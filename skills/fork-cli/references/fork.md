# フォークの記録

`SKILL.md` から、共通の節と、選んだ種類の節、プロンプト、戻り文面、`result.md` を読んでください。選んでいない種類の節は読みません。

1件は、その呼び出しで指定した、実装または文書作成のどちらか一方の依頼です。区切りはファイル数ではありません。関連パスは複数のファイルになってよいです。

## 共通

`fork.md` に次の項目を書いてください。

- 作業ディレクトリ
- 種類（実装または文書作成）
- 引き継ぎ先の CLI 名
- 目標
- 決まっていること（既存の文書にある場合はパスまたは URL）
- 対象外
- 関連パス
- メインセッションへ戻してほしい結果

実装で戻してほしい結果は、変更の要約と確認結果です。文書作成で戻してほしい結果は、成果物のパスです。

## 実装

共通の項目に加え、変更の完了条件と確認方法を書いてください。

この種類では、フォークに文書作成の指示がある場合を除き、新しい文書を作りません。

## 文書作成

共通の項目に加え、読み手、成果物のパス、形式を書いてください。

この種類では、フォークにコード変更の指示がある場合を除き、コードを変更しません。

## プロンプト

`prompt.md` は、引き継ぎ先へ送る自己完結の指示です。引き継ぎ先にこのスキルが入っていることは前提にしません。本文は次の項目を含めてください。

- `fork.md` の絶対パスを読み、そこに書かれた1件だけを行うこと
- 種類が実装なら、指示がある場合を除き新しい文書を作らないこと
- 種類が文書作成なら、指示がある場合を除きコードを変更しないこと
- コミットと push は、`fork.md` に明示があるときだけ行うこと
- API キー、パスワード、個人を特定できる情報をファイルや出力に書かないこと
- 作業が終わってから `result.md` を作成し、途中のファイルは作らないこと
- `result.md` の末尾を `状態: 完了` にすること
- `.fork-cli/` をコミット対象に含めないこと

## 戻り文面

サブエージェントを使えないとき、利用者には次の文面を渡してください。`<結果の絶対パス>` は、完成後の `result.md` の絶対パスに置き換えます。

```text
fork-cli の結果を読んでください。
結果: <結果の絶対パス>
```

## result.md

引き継ぎ先が書き終えたときに作る項目です。末尾の行は `状態: 完了` にしてください。

- 行ったこと
- 成果物のパス
- 確認したこと
- 状態: 完了
