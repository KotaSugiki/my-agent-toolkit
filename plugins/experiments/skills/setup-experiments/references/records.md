# 実験情報の記録形式

前提・目標値・実験記録はMarkdown、レポートはHTMLで保存します。計画は既存の形式にかかわらず必ず `.md` ファイルでも出力します。以下は導入先リポジトリからの相対パスです。既存の保存先を使う場合は、実際の場所と対応関係をプロジェクトの前提に記します。

未確認、未準備、該当なしを区別し、理由と次に必要な作業を添えます。版は `project-v1`、`targets-v1` のように付け、変更時に番号を増やします。確認には確認者、日時、確認内容、回答の所在を記録します。未回答は確認待ちのまま保持します。

## プロジェクトの前提：docs/experiment-project.md

- 前提の版、更新日、既存リポジトリ・新規プロジェクトの区分。
- 目的・目標：何を実現したいか。対象範囲と対象外。
- データ：所在、取得方法、版、分割、利用上の制約。
- 実行手順：コマンド、作業ディレクトリ、設定。根拠となるコード・文書。
- 環境：依存関係、機器・サービス、準備状況。
- 条件：変更できる項目、固定する項目。
- 評価方法：測定・集計方法と根拠。計画で決める目標値は評価指標・目標値の文書を参照。
- 制約：実行回数、時間、費用などの上限と未確定の上限。
- 保存先：評価指標・目標値、実験記録、設定、出力、ログ、レポート、フィードバックの場所。
- フィードバック：誰がどこへ記録するか、回答の原文または参照、次の計画への反映方法。
- 未確認・未準備の項目、項目ごとの人間の確認記録。全項目の内容または未準備・該当なしの理由を対話で確認するまで、文書の状態は「対話中」とします。回答待ちがなくなったら「確認済み」とし、実験の実行準備の状態は別に記します。
- 更新履歴：変更理由、変更箇所、影響する計画。

## 評価指標・目標値：docs/experiment-targets.md

実験計画の担当が作成します。セットアップでは新規の値を定めません。

- 目標値の版、対応するプロジェクトの目標・前提の版。
- 指標ごとに名称、算出方法、単位・分母、対象データ、集計範囲、望ましい方向。
- 具体的な目標値、その根拠となる要求・資料・基準測定、比較対象、副作用を測る指標。
- 仮説の支持・反証・判断不能と、目標達成・未達を判定する基準。
- 人間の確認状態と確認記録。初回と、値・指標・測定方法・判定基準を変える際に確認します。
- 更新履歴：旧版、変更理由、比較できなくなる実験。旧版の内容を保持します。

## 実験記録：docs/experiments/<experiment-id>.md

IDは `exp-20261006-001` のように一意に付け、既存IDとの重複を確認します。条件・仮説を変更した新しい検証には新しいIDを使い、前のIDを参照します。同じ計画内の反復・再試行には実行番号を付けます。

1. **識別情報**：実験ID、前の実験ID、作成日、現在の段階、前提と目標値の版、関連ファイル。
2. **計画**：目的、仮説、前提・指標・目標値・判定基準の写し、目標値の確認記録への参照、比較条件・固定条件、データ、反復、乱数の種、実行・評価手順、上限、中止条件、実行準備、前回のフィードバックと反映内容。
3. **実行**：実行番号ごとの条件・設定、コードと環境、コマンド・作業ディレクトリ、開始・終了日時、所要時間、終了コード、成功・失敗・未実行の状態、出力・ログの参照、計画からの逸脱。未実行には理由を付けます。
4. **結果**：実行番号ごとの観測値、単位・分母、評価対象、元の結果の参照、欠測と理由。
5. **評価・分析**：比較対象との差、目標達成の判定、仮説を支持する結果・反する結果・判断できない点、各根拠、推測、限界、追加検証案。
6. **レポート**：結論の短い要約、HTMLレポートへの相対リンク、人間に判断してほしい点。目的・方法・結果・考察の詳細と参照資料はHTMLや元の記録へ参照し、本文を重複させません。
7. **人間のフィードバック**：回答待ちの事項、実際の回答または参照、回答者と日時、継続・変更・追加検証・終了の判断、次の実験IDと反映先。

未着手の節は未着手と記し、他の担当へ引き継ぎます。設定・大きい出力・ログは前提で指定した保存先の実験ID配下へ置き、実験記録から参照します。過去の計画と観測結果は保持し、訂正には理由と日時を付けます。

計画は草案・確認待ちでも実験記録の「計画」へ保存します。正式な保存先が決まっていない場合は一時的な `.md` ファイルに保存し、その場所を返します。正式な保存時に内容と版の対応を記録します。

HTMLレポートの既定の保存先は `docs/experiments/<yyyymmdd>-<experiment-id>-report.html` です。実験IDで計画・結果・評価と結び、既存レポートの更新では名前を変えません。必要なCSS・JavaScriptもレポートから参照できる場所へ保存します。グラフの元データ、単位・集計範囲、欠測の扱いを残し、切り替えや折りたたみで詳細を確認できる構成にします。
