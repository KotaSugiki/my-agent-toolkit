# 実験の前提をセットアップする

プロジェクトの目標と、繰り返し利用する前提情報を、必ず利用者との対話で整理します。このスキルだけで利用できます。実験支援エージェントの導入や実験の実行は行いません。

## 開始条件

利用者がセットアップの開始・更新を依頼したときに開始します。スキルの導入、ファイルの閲覧、使い方の質問だけでは、`experiment project`（実験プロジェクトの前提文書）の作成・更新を始めません。親エージェントから依頼された場合も、利用者への質問と回答の確認を親に依頼します。回答が届くまで保存を進めません。

## 手順

1. 導入先の規約、コード、設定、ドキュメント、既存のセットアップ情報を読みます。実行・評価方法の根拠を調べ、この段階では前提文書を作成・更新しません。条件・仮説だけの変更なら、保存情報の場所を示して終了します。
2. [記録形式](references/records.md)の項目に沿って、調査結果の短い要約と不足項目を提示します。既存リポジトリか新規プロジェクトかは実験に関する資産で判断します。目的・範囲と保存先について確認質問を送り、回答を待ちます。情報が揃っていても、調査結果を今回の前提として使うことを対話で確認します。
3. 回答を反映し、残る項目を少数ずつ質問します。調査済みの情報は根拠付きの候補として示し、同じ情報の入力を求めません。目的・目標、対象範囲、データ、実行手順・環境、変更条件・固定条件、評価方法、制約、保存先、フィードバックの記録方法を対話で確認します。未確認の情報は推測で埋めず、未準備の項目には必要な作業と妨げる実験段階を記します。
4. 目的・範囲と保存先への回答を受け取った後は、確認した内容を合意した保存先へ順次反映します。必要項目の確認中は「対話中」の草案とし、未回答を確認待ちで残します。同じ保存先への追記ごとに保存の許可を求める必要はありません。更新時は既存の目標値、実験記録、フィードバックを保持し、変更理由、変更箇所、前提の版、影響する計画を記録します。
5. セットアップの目標には「何を実現したいか」を記します。「どう測るか」「どこまで達成するか」は実験計画で具体化します。既存の評価指標・目標値は参照し、利用可能な評価方法と区別します。値を新たに決めたり、既存の値を変更したりしません。
6. 全項目の確認状況と残る準備を短く提示します。全項目について内容、または未準備・該当なしの理由を対話で確認できたら「確認済み」として保存します。未回答があれば「対話中」のまま、次に必要な質問を残します。未準備の項目を確認できても、実験の実行準備が整ったことにはしません。

## 完了条件

全項目の内容または未準備・該当なしの理由を利用者との対話で確認し、回答の所在と共に保存できたら完了です。未回答が残る場合は完了と報告しません。報告は保存先、前提の版、確認状態、次に進める範囲、残る準備を簡潔に示します。
