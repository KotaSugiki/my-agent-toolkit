# 親エージェントの進行手順

全体進行を依頼された親が、この手順を読みます。4担当を順番に呼び、成果物を受け取ってから次へ進めます。個別担当だけの依頼では、その担当で終えます。

## 準備と再開

前提、評価指標・目標値、最新の実験記録とフィードバックを読みます。再開時は実験IDと未着手・失敗・回答待ちの節から再開位置を定めます。既に終えた実行を再実行しません。

前提が保存済みで変わっていなければ、そのまま使います。初回や目的・データ・環境の変更時は、利用者との対話で前提を整理します。スキルやエージェントの導入だけでは始めません。`setup-experiments` の利用が依頼されていればその手順を使い、未導入なら生成された担当の記録形式に沿って、調査結果・目的・範囲・保存先を利用者に提示して回答を待ちます。回答後は確認した内容を順次保存し、全項目の確認が揃うまで「対話中」として不足を質問します。回答待ちの間は次の段階へ進めません。別のスキルの導入を進行の条件にしません。

## 一回の実験

1. `experiment-planner` に、前提・目標値の保存先、前回の実験ID、フィードバック、今回検証したいことを渡します。新しい実験ID、Markdownの計画ファイル、確認事項を受け取ります。草案・確認待ちでも `.md` ファイルの保存先と内容を確認します。
2. 初回の評価指標・目標値、または値・指標・測定方法・判定基準を変更した場合は、根拠と比較条件を人間へ提示し、回答を記録します。確認済みの目標値を引き継ぐ条件変更では再確認を求めません。計画が制約・権限の範囲内で、必須の準備と確認が揃った場合に実行可能とします。回答が必要な項目は、未回答のまま実行へ進めません。
3. `experiment-runner` に、実験IDと計画、設定・結果・ログの保存先を渡します。全条件の状態と出力を確認します。失敗時は取得できた結果と失敗記録で続けられる範囲を決めます。条件変更が必要なら計画へ戻します。
4. `experiment-analyst` に、実験IDと計画・実行・結果の保存先を渡します。判定の根拠と判断不能の理由を確認します。失敗だけでも評価できる範囲と不足を報告させます。
5. `experiment-reporter` に、実験ID、全成果物の保存先、利用者が指定したHTMLスキルや表示の希望を渡します。簡潔なHTMLレポート、グラフなどの視覚表示、操作の確認結果、判断事項を確認し、短い要約とレポートへのリンクを人間に提示します。回答待ちを保存し、一回の進行を止めます。

## フィードバックと次の実験

人間の回答の原文または参照、回答者、日時、判断を対象IDに追記します。続ける場合は判断を次の計画へ反映させます。新しい実験IDから前のIDへ参照を付け、前の記録にも次のIDと反映先を追記します。

仮説・パラメータだけの変更では前提と目標値を引き継ぎます。目的・前提が変われば前提を更新し、目標値への影響を計画担当と確認します。目標値などの変更には新しい版と人間の確認記録を残します。

終了の判断は実験記録に記します。未回答は回答待ちを保ち、継続依頼を受けた時点で再開します。
